# Verify 重复返工的候选设计

## 已确认的范围

- 在 Windows 五仓 v0.1.5 安装包中，第一次可归属的 A 检查失败后只重做了 A。第二轮 Verify 的声明输入指纹、失败检查和受影响范围相同，旧 Runtime 又创建了 Build Plan。B、C、D 完成事实仍有效。
- Open 已批准。修复已复现的重复自动派工，保留真实变化、首次失败、人工继续和恢复规则。现场报告首次失败的原因仍缺原始机器证据。
- 未提出 Spec Patch。正式 Design 仍由当前 Wait 决定。

## 候选方案

1. **识别无进展。** 沿用 `EvidenceCoordinator.verifyRepairFacts` 验证失败、覆盖和影响范围。从当前 Build Protocol 上一轮 Verify 修复来源读取原机器 Attempt 与 Bundle，核对 Run、Verify、Profile 和冻结输入的归属。用现有声明输入指纹、验收集合、失败或因果阻断的检查及相应验收比较两轮证据。对失败检查及其上游依赖，比较已验证回执的有效输入指纹，包含实际消费的生产者内容摘要。Work、epoch、Attempt、Bundle、回退决定和完成记录 ID 只供追溯。首次失败或有效变化继续局部修复。上一轮证据不可观察或归属不明时，保留当前 Work 待重观。
2. **一次原子暂停。** 在第二次同输入、同失败的证据校验完成后，通过 Lifecycle 守卫持久化 Verify 待决定。当前 Work、epoch、已接受 Host Review、候选机器结果和有效完成事实保留。`status` 只读显示已提交状态。冷恢复、重复拉取和显式机器 Verify 先查同一暂停，领取和执行入口也受等待状态约束。事实未变时不派发 Build 或新的机器 Attempt。输出列出检查 ID、受影响验收、失败 Evidence 和可定位的诊断。
3. **同一个 Run 继续。** 复用 `run decision` 及 `run decide` 现有协议，新增一个限于 Verify 返工的决定类型。用户可批准一次局部返工，也可以把该请求保留为待决定。批准时核对当前 Run、Work、epoch、提案和原失败事实，在同一次受保护转换中消费决定并执行 `revise-implementation`，由 Runtime 派发普通 `build.plan`。旧请求、冲突答复和并发重放都不会重复派发。Evidence 工作区恢复增加仅针对这类 Verify 等待的重观分支。项目身份、规划和权限仍先按原规则处理。确认实际声明输入变化时，以同一次受保护转换清除对应等待、递增 epoch 并沿原证据失效路径重新验证。暂时无法完成观察时保留等待，不接受继续答复。
4. **恢复边界。** 在启动机器检查之前，为当前 Run、Work 和 epoch 保存可恢复的 Attempt 绑定。证据写成后到生命周期结算前，即使换进程或传入另一 Attempt，也复用同一份证据，直到受保护结算。暂缓和批准在各自的受保护提交中重新核对当前版本、Work、epoch、Attempt、Host 审查回执及实际输入，基于现有 `assessInputs` 核对派生依赖变化。失效转换提交前也要重新核对它绑定的输入观察。旧执行的报错不能给更新的 Work 写恢复指引。从已提交的生命周期事实构造当前和历史决定视图，允许同一答复幂等提交。一次明确批准仅授权一轮返工，经批准的返工仍无进展时会再次暂停、展示新一轮失败证据。用户可针对这次新的失败再次决定是否授权一轮。真实修复通过机器检查后正常进入 Archive。

## 取舍

- Comet Native 用可信失败签名、持久暂停和受控继续来制止循环。本候选采用相同控制方式，对已经证明实际输入与失败范围完全相同的路径在第一轮自动返工后暂停。首次失败和有实质变化的返工不会因为一个全局重试计数提前停。
- 只在 CLI 返回临时诊断无法保证冷恢复后仍以原事实为准。复用既有等待、审批身份和轨迹承诺，同时给 Verify 的继续处理限制明确的授权范围。
- 声明输入指纹按当前 Evidence 策略计算。有仓库显式声明 Git 身份或运行环境是输入时，仍按该策略判定实际变化。
- 暂停、失败详情和请求都从同一条已提交的 Wait 投影。底层 `evidence run --workflow-run` 也受 Attempt 绑定约束。生命周期定义新增转换时，验证已有的定义摘要兼容机制能读取本次改动前的活动状态。本轮验收承诺候选包内冷恢复，不为已卡住的历史 Run 增加迁移逻辑。

## 验证

- 单元对照首次失败、同指纹同失败、仅运行标识变化、真实输入变化、证据归属错误和未知结果。
- CLI 生产入口验证两种冷恢复顺序，以及机器结果已写成、暂停提交前断开时复用原 Attempt。覆盖直接 Verify 和并发不同 Attempt、派生输入变化、旧答复拒绝、有效答复重复提交。
- Windows 五仓实际安装包复现反例与真实修复。确认接受过的无关包保留完成事实，同一个 Run 能验证通过并进入 Archive。

## 已确认

用户已批准该方案及执行配置，沿用本独立 worktree，使用 autonomous + TDD + thorough。正式设计见 `design.md`。
