# Design

## Context

阶段审批已经各自使用规划语义和当前提案。旧命令把手动观察直接写入通用 Specification Usage Snapshot。Open 与 Design 又分别调用该写入接口，使第一次写入的摘要与合法阶段迭代冲突。部分后续阶段恢复入口还把不可用观察归为语义漂移。

## Goals / Non-Goals

**目标**

- 让校验观察、阶段接受和 Provider 兼容性各自使用对应的身份与授权。
- 保留现有的 Open、Design、Verify 和 Archive 恢复规则，统一 Provider 不可用分支的行为。
- 通过公开 CLI、安装包和真实多仓验收覆盖错误入口、正常推进与冷恢复。

**范围边界**

- 本次聚焦规格校验和规划观察。已有错误绑定现场保留用于复现，历史记录的处置在能证明其来源时由单独的恢复决定处理。
- 复用当前 OpenSpec Store、阶段守卫、Run Store 和规划恢复分类。

## Decisions

1. 沿用 Comet Classic 0.5.1 的 Evidence 提交顺序。重新观察当前证据，核对归属和阶段，验证后由 Runtime 在受保护提交中接受。手动命令报告本次校验结论，不取得阶段推进权。
2. 分开 Provider 身份和阶段校验摘要。Provider 不兼容继续阻断，已批准草案仍按现有规划语义和审批事实检查。合法 Open 到 Design 深化使用各自证据。
3. 让 Build、Verify 和 Archive 入口对未知观察采用一致的重试语义。证实规划失效时沿用现有 Design 修订和依赖失效。
4. 在真实公开入口重现异常；验证状态、checkpoint 和历史权限在失败、中断与冷恢复前后可核对。最终验收覆盖多仓 Verify、复选框提交、Archive 及实际规划变更。

## Risks / Trade-offs

- 文档现在声明 `--run` 具有绑定效果，需和 CLI 契约一并更新。Design 阶段核对既有调用者和剩余写入口。
- 旧 Run 的绑定只保存摘要，无法仅凭它判断当时的校验结论。根据历史来源决定是否另做有证据的恢复。
- 阶段接受与校验观察之间可能有并发变更。验证原子提交和版本检查是进入 Build 前需要明确的设计约束。
