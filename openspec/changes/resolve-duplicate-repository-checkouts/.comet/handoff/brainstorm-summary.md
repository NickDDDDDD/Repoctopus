# Design 讨论摘要

状态为候选，待当前 Design 决定。

## 已确认范围

Open 已批准。保留现有的轻量接入流程，解决两个 checkout 指向同一远端时的选择，正式配置中的远端身份保持唯一。Windows 老行为已用公共 CLI 复现。无需 Spec Patch。

## 候选方案

- Git 平台适配器在接入探测时返回冲突组的规范化路径和远端身份。常规仓库快照只接收解析后的唯一集合，经作用域检查后对别名去重。
- `project detect` 通过接入草稿返回冲突目录和可执行的解决方式。保留 `--repositories` 的逻辑 ID 筛选，新增可以重复传入的 `--checkout <path>`。每个参数给一个实际目录，路径允许使用引号包裹的绝对路径或相对于 Workspace 的路径。显式选择只能匹配当次扫描发现的 Git 根。
- 有效的已登记路径优先复用原 ID。当请求没有显式缩小范围时，未解决的远端冲突阻止创建批准请求。显式选仓可以排除其他组。`project prepare` 同样检查冲突，避免手改候选绕过选择。
- CLI 和 Init Skill 读同一组诊断。Agent 仅在同一远端不能确定目标时请用户选目录，仍由既有接入审批确认最终 Workspace、仓库及 Store pointer。未选 checkout 不参与 pointer、Verify 或入口安装。
- 将已选仓库的规范路径和远端身份与现有候选摘要绑定。复用 `assertDetectedRepositoryScope` 的 Git 观测，在准备、批准及恢复原请求时按冻结事实核对。由 Store 事务继续管理已经产生的逐仓回执。

## 取舍与验证

启用自动首选会把实际写入位置交给扫描顺序。给副本各自分配正式 ID 会使后续恢复和发布无法确定目标。要求所有用户一律改用路径也会让无冲突接入变复杂。只对歧义组收集路径，保持普通场景走原有命令。

测试先复现静默丢失，再用实际 Windows 安装包验证冲突展示、引号路径、显式排除、非选中仓无写入、登记复用，以及审批间 checkout 变化的拦截。端到端通过接入和工作流入口核对结果。
